# here.now integration

Mira can inspect one provisioned here.now account, its site inventory and a selected site's current version, file metadata and access policy. These are passive reads through the existing tool router and receipts. They do not publish, overwrite, restore versions, upload/download file bytes, change access, send invitations, buy domains or enumerate API keys.

Supply the same `HOMELAB_MIRA_HERENOW_OWNER` (Homelab account ID) and immutable `HOMELAB_MIRA_HERENOW_ACCOUNT_ID` to dashboard and Mira. Only Mira receives `HOMELAB_MIRA_HERENOW_API_KEY`. The account selector is fixed server-side on every request; model inputs cannot switch accounts or request `scope=all`. The provider must confirm the selected account ID and active membership before returning any site data. The model child receives no provider credential.

The shared Integrations card has independent enable/pause, reason and timed resume. A grant binds the exact account mapping. Every read rechecks binding, fresh dashboard evidence, control version and execution lease before and after network activity. Responses arriving after pause, regrant, receiver replacement or lease loss are discarded. Timed resume requires matching fresh service evidence; replacing an account cannot silently adopt old consent. Provider read failures remain redacted and retryable without fencing unrelated tools.

Requests use GET on `https://here.now/api/v1/`, with redirects disabled, a 2 MiB response cap (8 MiB for access policies) and 15-second deadline per request. Only `accounts`, selected-account `publishes`, `publish/{slug}` and `publish/{slug}/access` are exposed. No public site URL is visited. Returned links are constructed from validated slugs, and unknown provider fields are excluded.

The selected-account list is not provider-paginated; the documented `limit`/`cursor` parameters apply only to `scope=all`. Mira returns at most fifty rows with an explicit truncation flag, accepting at most 5,000 rows within its byte budget. One site's manifest is capped at one hundred displayed entries with explicit truncation. Details retain current version/source and access-policy version, but the two reads are separate observations, not an atomic snapshot or approval to overwrite. Restricted email/domain allowlists accept the provider's [documented 10,000-entry limit](https://here.now/docs#access-api) per list within the byte budget. Results show at most one hundred entries per list with total counts and separate truncation flags; these partial observations cannot be used to replace full access lists. The allowlists are private metadata available only in the owner's conversation. Passwords, claim tokens, billing data and unrelated memberships are excluded.

The API follows the official [here.now documentation](https://here.now/docs) and [OpenAPI contract](https://here.now/openapi.json), alongside canonical skill version 1.33.0. These are contract references, not changing executable instructions. The adapter ships in Homelab's versioned builds and updater; no separate package or local third-party patch is installed. Existing credentials are not discovered from legacy profiles.

Synthetic tests cover account selection/membership, bounded metadata projection, unsafe identifiers, unknown access modes, pause/regrant and receiver replacement, lease/cancellation fences, read retries, durable receipts and timed resume. Production account/API qualification remains a separate delivery step; development neither activates the live account nor publishes a site.

## Reviewed public publication

The chat's Publications library can prepare new public sites from selected owned files. Mira can also prepare drafts using only files shared in its current conversation, including a full replacement for an existing public site. Drafts never grant publishing permission. The operator reviews the exact title, destination, visibility, file paths and downloadable source files, then selects **Publish publicly**. The server captures file hashes and verifies the reviewed snapshot again before queuing. An update requires the existing site's slug and reviewed `baseVersionId`; a changed version or pending update returns the draft for fresh review.

Provision the optional `HOMELAB_MIRA_HERENOW_PUBLISH_API_KEY` only in the Mira executor. The read credential remains required. An unset or empty optional publishing key leaves read-only operation available; malformed nonempty values are rejected. Both keys must reach the same configured account; publication preflight checks membership using the publishing credential. The dashboard and model process receive neither key. No publishing key means drafts can be prepared, but publication approval cannot proceed. This code adds no live credentials or account activation.

Publications allow at most eight files totaling 25 MiB: UTF-8 HTML, CSS, JavaScript, JSON, text, Markdown, CSV and SVG, plus detected PNG/JPEG/WebP/PDF. Paths must be relative and unique; dot-directories, traversal, remote URLs and provider configuration manifests are rejected. Files are served as downloadable attachments for review, never executed inside the dashboard. Manual conversations can create UTF-8 artifacts with `mira_file_create`; the resulting owned attachments can be selected just like uploaded files. Binary generation is not implemented.

A separate executor loop delivers approved publications without consuming the infrastructure worker slots or requiring a running model. It admits at most one publication per owner at a time. Approval expires after fifteen minutes. Pause, regrant, account replacement, stale service evidence and removed files prevent subsequent external steps. Removing the executor configuration or its publishing key revokes queued approvals even if the dashboard still has the old mapping; restoring configuration requires a new review. Cancel is available before dispatch. A request already in flight may have completed externally when a pause arrives; the durable result then requires inspection.

The publisher uses the fixed here.now API for staging and finalization, and validated signed HTTPS `*.r2.cloudflarestorage.com` URLs for file uploads. Uploads never receive API credentials or cookies and never follow redirects. API responses are bounded; individual requests and the whole write attempt have deadlines. Uploads retain the complete reviewed MIME type, including its charset; staging cannot replace these parameters. The final check verifies the exact reviewed title, live version, file manifest (including MIME parameters) and public access. New sites request permanent persistence and explicitly set public access with `notify: false`. Existing public updates preserve their access policy.

Private publishing is not offered: the provider rejects access changes before a new site is finalized, so this implementation does not briefly publish private content and then restrict it. Every approval explicitly permits anyone with the link to read all selected files. It does not authorize invitation emails, domain purchases or access-list changes on existing sites.

Known site/version references are persisted between stages. A lost or malformed creation acknowledgement may leave no known site reference. Any uncertain write becomes **needs attention**, retains available references and is never automatically replayed. Inspect the here.now account before preparing another attempt. Interrupted attempts recover to the same visible state after three minutes. Failed read-only preflight checks defer that draft briefly so other queued drafts can proceed. No remote site deletion or rollback is implicit.

The `mira_publications` migration, executor configuration, local tools and shared chat dialogs ship in the ordinary Homelab release. Synthetic PostgreSQL and HTTP tests cover exact approval, file ownership and hashes, pause/removal during upload, stale versions, concurrent attempts, expired approvals, ambiguous writes, recovery and service freshness. Live publication and account qualification remain pending until deployment.
