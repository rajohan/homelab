# here.now metadata reads

Mira can inspect one provisioned here.now account, its site inventory and a selected site's current version, file metadata and access policy. These are passive reads through the existing tool router and receipts. They do not publish, overwrite, restore versions, upload/download file bytes, change access, send invitations, buy domains or enumerate API keys.

Supply the same `HOMELAB_MIRA_HERENOW_OWNER` (Homelab account ID) and immutable `HOMELAB_MIRA_HERENOW_ACCOUNT_ID` to dashboard and Mira. Only Mira receives `HOMELAB_MIRA_HERENOW_API_KEY`. The account selector is fixed server-side on every request; model inputs cannot switch accounts or request `scope=all`. The provider must confirm the selected account ID and active membership before returning any site data. The model child receives no provider credential.

The shared Integrations card has independent enable/pause, reason and timed resume. A grant binds the exact account mapping. Every read rechecks binding, fresh dashboard evidence, control version and execution lease before and after network activity. Responses arriving after pause, regrant, receiver replacement or lease loss are discarded. Timed resume requires matching fresh service evidence; replacing an account cannot silently adopt old consent. Provider read failures remain redacted and retryable without fencing unrelated tools.

Requests use GET on `https://here.now/api/v1/`, with redirects disabled, a 2 MiB response cap (8 MiB for access policies) and 15-second deadline per request. Only `accounts`, selected-account `publishes`, `publish/{slug}` and `publish/{slug}/access` are exposed. No public site URL is visited. Returned links are constructed from validated slugs, and unknown provider fields are excluded.

The selected-account list is not provider-paginated; the documented `limit`/`cursor` parameters apply only to `scope=all`. Mira returns at most fifty rows with an explicit truncation flag, accepting at most 5,000 rows within its byte budget. One site's manifest is capped at one hundred displayed entries with explicit truncation. Details retain current version/source and access-policy version, but the two reads are separate observations, not an atomic snapshot or approval to overwrite. Restricted email/domain allowlists accept the provider's [documented 10,000-entry limit](https://here.now/docs#access-api) per list within the byte budget. Results show at most one hundred entries per list with total counts and separate truncation flags; these partial observations cannot be used to replace full access lists. The allowlists are private metadata available only in the owner's conversation. Passwords, claim tokens, billing data and unrelated memberships are excluded.

The API follows the official [here.now documentation](https://here.now/docs) and [OpenAPI contract](https://here.now/openapi.json), alongside canonical skill version 1.33.0. These are contract references, not changing executable instructions. The adapter ships in Homelab's versioned builds and updater; no separate package or local third-party patch is installed. Existing credentials are not discovered from legacy profiles.

Synthetic tests cover account selection/membership, bounded metadata projection, unsafe identifiers, unknown access modes, pause/regrant and receiver replacement, lease/cancellation fences, read retries, durable receipts and timed resume. Production account/API qualification and reviewed publication are separate delivery steps; development neither activates the live account nor publishes a site.
